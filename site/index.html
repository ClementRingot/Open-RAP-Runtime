Vos business objects RAP,
sans système SAP.

Écrivez votre BO comme dans ADT — tables, vues CDS, annotations, behavior definition, behavior pool en ABAP. rap-transpiler en fait une application qui tourne partout : un service OData V4, le runtime RAP managed avec votre code ABAP, PostgreSQL et une interface Fiori. Les mêmes sources s'importent ensuite dans SAP avec abapGit.

Comment ça marche

Un compilateur lit vos sources abapGit et génère une application Node.js. Rien de propriétaire : ni SAPUI5, ni CAP.

Tout un BO RAP

Runtime RAP managed

Verrous, ETags, numérotation, autorisations globales et d'instance, feature control, déterminations, validations, actions, savers.

Draft comme Fiori Elements

with draft et with collaborative draft : brouillons, Edit / Activate / Discard, état d'édition, invitation d'autres utilisateurs.

Votre ABAP, exécuté

EML complet, messages, ABAP SQL, AUTHORITY-CHECK, classes libérées : JSON, HTTP, bgPF, e-mail, numérotation.

UI Fiori générée

List Report, Object Page, Worklist, Analytical List Page, Overview Page, Form Entry ; filtres, variantes, value helps.

CDS récents

Table entities, types simples et énumérés, vues standards (I_Currency, I_Country…) avec leurs données.

API Web et OAuth 2.0

Binding Web API, jetons OIDC (client credentials, PKCE), serveur OAuth de développement intégré.

Agents IA (MCP)

Le service devient un serveur MCP : chaque outil applique les contrôles du BO.

Fidèle à SAP

Mode standard : ce qui se construit s'active sur SAP. Mode enhanced pour les extensions.

Déploiement

Docker, docker compose, SAP BTP Cloud Foundry (cf push), n'importe quel serveur Node.js.

Démarrer en deux minutes

  1. Installez l'extension (elle contient tout : rapt, OpenUI5, une base embarquée).
  2. RAP : Nouveau business object crée un BO managed complet, avec des données.
  3. RAP : Lancer rapt dev ouvre l'application ; elle se reconstruit à chaque enregistrement.
  4. RAP : Nouvel objet RAP (assistant) ajoute vues, BDEF, services… comme dans ADT.

Ou en ligne de commande

rapt new mon-projet Travel --prefix ZRT
rapt dev mon-projet
# http://localhost:8080/

rapt check mon-projet       # diagnostics
rapt build mon-projet --out dist
rapt abapgit mon-projet     # XML pour SAP

Questions fréquentes

Faut-il une licence SAP ?

Non. rap-transpiler n'utilise aucune bibliothèque SAP propriétaire : OpenUI5 (Apache 2.0), abaplint (MIT), PostgreSQL. Les sources restent les vôtres et s'importent dans un système SAP avec abapGit.

Mon BO se comportera-t-il comme sur SAP ?

C'est la règle du projet : en mode standard, une source se comporte comme sur SAP, et ce qui ne s'y activerait pas est refusé avec un diagnostic. Les écarts connus sont documentés.

Et en production ?

L'application générée est une application Node.js ordinaire : Docker, Kubernetes, SAP BTP Cloud Foundry, avec PostgreSQL et l'authentification OIDC de votre fournisseur d'identité (Keycloak, SAP Cloud Identity Services, Entra ID…).

Où est la documentation ?

Dans le guide, et dans le launchpad de rapt dev (tuile Documentation).
