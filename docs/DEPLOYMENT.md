# Deploying an application or a launchpad

An application generated by `rapt build` (or a launchpad by `rapt launchpad`) is a standalone
folder: Node.js 22, a `package.json`, a `Dockerfile`, a Cloud Foundry `manifest.yml`. It deploys
anywhere Node.js or a container runs ([D50](DECISIONS.md)).

## What to set outside `localhost`

| Variable | Why |
|---|---|
| `PUBLIC_URL` | The address the users see (`https://travel.example.com/`): OIDC redirects. Derived from the route on Cloud Foundry. |
| `AUTH_MODE=oidc`, `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` | An identity provider: SAP Cloud Identity Services (IAS), Keycloak, Microsoft Entra ID, Auth0… Never expose `AUTH_MODE=none` on a network. |
| `SESSION_SECRET` | A long random value, the same for the launchpad and its applications. |
| `DATABASE_URL` (and `DATABASE_CA`) | A PostgreSQL (14 or later) and, if needed, the certificate of its server. Derived from a bound PostgreSQL service on Cloud Foundry. |
| `OIDC_REQUIRED_ROLE` | Optional: the role without which the application refuses access. |

All the variables are in the generated `.env.example`. Secrets never go into `manifest.yml` nor
into the repository.

## Docker (VM, Kubernetes, Azure Container Apps, Google Cloud Run…)

```sh
rapt build my-project --out out/travel
cd out/travel
docker build -t travel .
docker run -p 8080:8080 --env-file .env travel
```

The generated `docker-compose.yml` starts the application with PostgreSQL (and Keycloak with
`--profile oidc`): useful for a test server.

## SAP BTP, Cloud Foundry environment

```sh
rapt build my-project --out out/travel && cd out/travel
cf create-service postgresql-db <plan> travel-db       # the name manifest.yml expects
# manifest.yml: fill in OIDC_ISSUER and OIDC_CLIENT_ID (IAS application with OpenID Connect)
cf push --no-start
cf set-env travel SESSION_SECRET "$(openssl rand -hex 32)"
cf set-env travel OIDC_CLIENT_SECRET <secret>
cf start travel
```

The runtime reads `VCAP_APPLICATION` (route → `PUBLIC_URL`) and `VCAP_SERVICES` (bound
PostgreSQL → `DATABASE_URL`, `DATABASE_CA`). The Node.js buildpack installs the dependencies
(`vendor/` contains the runtime of rap-transpiler). Health check: `/health`.

For a launchpad: push each application, then give their routes to the launchpad
(`cf set-env launchpad APP_TRAVEL_URL https://travel.cfapps…`); the launchpad and its
applications share `SESSION_SECRET` and the same OIDC client.

## A machine of the network

```sh
npm install && npm start             # listens on 0.0.0.0:8080 (HOST, PORT)
```

During development, `rapt dev --host 0.0.0.0` also opens the development server to the network
(colleagues, phone), still without sign-in: keep it to a trusted network.

## HTTPS

The application speaks HTTP; TLS terminates in front of it (Cloud Foundry router, Kubernetes
ingress, nginx or Caddy reverse proxy, managed service of the cloud). `PUBLIC_URL` gives the
HTTPS address.

## Publishing a version of rap-transpiler (maintainers)

A tag `v1.2.3` runs `release.yml`: the VS Code extension (GitHub release, Marketplace with the
`VSCE_PAT` secret, Open VSX with `OVSX_PAT`) and the CLI on npm ([D65](DECISIONS.md)):
`rap-transpiler` (the `rapt` command), `@rap-transpiler/model`, `@rap-transpiler/compiler` and
`@rap-transpiler/runtime`, all in version 1.2.3.

Once, for npm:

1. Create the organization **`rap-transpiler`** on npmjs.com (free for public packages): it
   holds the `@rap-transpiler` scope.
2. Create a *Granular Access Token* (*Read and write*, packages `rap-transpiler` and scope
   `@rap-transpiler`, or the whole organization) and save it as the **`NPM_TOKEN`** secret of the
   repository (*Settings → Secrets and variables → Actions*).

Without `NPM_TOKEN`, the `npm` job builds and checks the packages (archives of `pnpm pack`
installed by npm, `rapt check` and `rapt build` of the fixture) but publishes nothing. npm
provenance (the link between the package and the workflow) is added when the repository is
public.

```sh
git tag v0.1.0 && git push origin v0.1.0
```
